# Deploying PayShield on Render (multi-service)

PayShield is a distributed system: a FastAPI backend, a background agent
Worker, a Vite/React dashboard, and several data stores (Redis, PostgreSQL,
Neo4j, optional Ollama). Render isolates each process, so we run the app as
**multiple independent services** connected over the network.

> The original one-page guide had a few factual mistakes. This document is the
> corrected, repo-accurate version. The code changes that make the standalone
> Worker work on Render (Redis event feed) are already in this branch
> (`store/redis_client.py`, `api/routes/return_risk.py`, `agents/worker.py`).

---

## 1. Architecture on Render

| Resource | Render type | Notes |
|---|---|---|
| **PostgreSQL** | Render managed Postgres | `DATABASE_URL` (`asyncpg`) |
| **Redis** | Render managed Redis | `REDIS_HOST` is a **bare hostname**, not a `redis://` URL; + `REDIS_PORT` / `REDIS_DB` / `REDIS_PASSWORD` |
| **Neo4j** | Neo4j Aura (external) | Render cannot host Neo4j |
| **Ollama (optional)** | external GPU host or disabled | see §7 |
| `payshield-api` | Web Service (Docker) | `uvicorn api.main:app` on `$PORT`; Render Disks for audit/explanation persistence |
| `payshield-worker` | Background Worker (Docker) | `python -m agents.worker`; consumes the **Redis feed** |
| `payshield-dashboard` | Web Service (Node) | builds the Vite SPA, serves `dist` on `$PORT` |

Two blueprint files are provided:
- `render.yaml` – declarative Blueprint for the three application services.
- `docker/Dockerfile.worker` – the worker image (identical Python stack as the
  API but runs the worker entrypoint). The dashboard can use the Node runtime
  in the Blueprint (recommended) rather than its Dockerfile.

---

## 2. Prerequisites

1. Push this repository to GitHub/GitLab/Bitbucket and **connect it to Render**.
   - In Render dashboard: **New → New Blueprint**, pick the repo (uses `render.yaml`)
   - or **New → Web Service / Background Worker** per service (manual, §4).
2. A Render account. **Do not use the free tier** for the API/Worker: the ML
   stack (torch, torch-geometric, xgboost, shap) needs ~1 GB+ RAM and free
   Background Workers do not auto-restart after sleeping. Use at least a
   `starter`/`standard` paid plan.

## 3. Provision the data stores (do this first)

### 3.1 Redis (Render)
1. Dashboard → **New → Redis**.
2. Note the **Internal Connection String**, but the app does **not** take a URL:
   copy `REDIS_HOST` (the hostname), `REDIS_PORT`, `REDIS_DB`, `REDIS_PASSWORD`.
   - `REDIS_HOST` must be the **hostname only** — e.g. `redis-xxxx.internal`
     — **not** `redis://redis-xxxx:6379` (see `configs/config_loader.py`).
   - Render's internal, non-TLS Redis is preferred. (The code has no TLS path,
     so Upstash's TLS-only endpoint will not connect without code changes.)

### 3.2 PostgreSQL (Render)
1. Dashboard → **New → PostgreSQL**.
2. Copy the internal connection string and rewrite it to the **asyncpg** scheme:
   `postgresql+asyncpg://USER:PASS@HOST:5432/DB` (the app imports `asyncpg`, see
   `.env.example`). This is `DATABASE_URL`.

### 3.3 Neo4j (Neo4j Aura, external)
The API connects to Neo4j and initializes its schema at startup
(`api/lifespan.py`). Create an Aura instance and set:
`NEO4J_URI=bolt+s://<host>:7687`, `NEO4J_USER`, `NEO4J_PASSWORD`.

> The API tolerates Neo4j/Postgres being temporarily unreachable (it logs and
> degrades), but full graph/investigation features require them. Redis is
> **required**: the scoring path and `/health` depend on it.

### 3.4 Ollama (optional)
Set `ENABLE_LLM_INVESTIGATOR=false` unless you have a reachable Ollama host,
in which case point `OLLAMA_BASE_URL` at it. Render has no GPU host for this.

## 4. Create the application services

### Option A — Blueprint (fastest)
Apply `render.yaml` by choosing **New → New Blueprint** and selecting your repo.
Render creates `payshield-api`, `payshield-worker`, `payshield-dashboard`.

Then open each service → **Environment** and fill the `sync: false` values:

**payshield-api**
```
REDIS_HOST          = (hostname from §3.1)
REDIS_PORT          = 6379
REDIS_DB            = 0
REDIS_PASSWORD      = (from §3.1)
DATABASE_URL        = postgresql+asyncpg://...   (from §3.2)
NEO4J_URI           = bolt+s://...               (from §3.3)
NEO4J_USER          = neo4j
NEO4J_PASSWORD      = (from §3.3)
FRONTEND_URL        = https://payshield-dashboard.onrender.com
ADMIN_PASSWORD      = <your dashboard admin password>
```
`JWT_SECRET`, `PAYSHIELD_DEV_API_KEY`, `ENCRYPTION_KEY` are auto-generated by
Render (from `generateValue`). Record their values — you must copy
`JWT_SECRET` and `ENCRYPTION_KEY` into the Worker so they match.

**payshield-worker** — set `REDIS_*`, `DATABASE_URL`, `NEO4J_*` exactly as the
API, and set `JWT_SECRET` / `ENCRYPTION_KEY` to the **same values** Render
generated for the API.

**payshield-dashboard**
```
VITE_API_URL = https://payshield-api.onrender.com
VITE_WS_URL  = wss://payshield-api.onrender.com
```
`VITE_*` (not `REACT_APP_*`) is mandatory — the SPA reads `import.meta.env`
(`dashboard/src/api/client.ts`, `dashboard/src/hooks/useWebSocket.ts`). These
are baked into the JS at **build time**, so they must be present before the
first build.

### Option B — Manual services
If you do not use the Blueprint, create each with **New → ...**:

| Service | New → | Environment | Build | Start |
|---|---|---|---|---|
| api | Web Service | Docker | (uses `docker/Dockerfile.api`) | (image default) |
| worker | Background Worker | Docker | (uses `docker/Dockerfile.worker`) | (image default) |
| dashboard | Web Service | Node | `npm install && npm run build` | `npx serve -s dist -l $PORT` |

For the Docker services point **Root Directory** at the repo root, **Dockerfile
path** at `docker/Dockerfile.api` / `docker/Dockerfile.worker`, and set the env
vars from §4 Option A.

> Why Docker for the API/Worker and not `pip install -r requirements.txt`?
> The requirements pull the **full** PyTorch wheel. `docker/Dockerfile.api`
> installs the smaller **CPU-only** torch wheel first
> (`pip install ... torch==2.12.0+cpu`), which plain `pip install -r` would not.
> The CPU image also sets `OMP_NUM_THREADS` for sane latency.

## 5. Persist storage (Render Disks)

Render's default disk is ephemeral and wiped on redeploy. Mount **Render Disks**
so the following survive restarts (the same directories `docker-compose.yml`
persists via named volumes):

| Mount path | What it holds |
|---|---|
| `/app/store/audit_logs` | hash-chained audit log (compliance) |
| `/app/store/feedback` | agent feedback |
| `/app/models/production/explanations` | L1/L2 explanation artifacts |
| `/app/compliance/reports` | compliance reports |

Mount at these **sub-paths**, never at `/app/store` or `/app/models` —
`store/` is the Python package and `models/production/` holds the `.pt` models;
a whole-directory mount would hide that code/data.

## 6. Environment variable summary

All secrets and data-store settings must be **identical across API and Worker**
except the port-facing `FRONTEND_URL` (API only).

| Variable | API | Worker | Dashboard |
|---|---|---|---|
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` / `REDIS_PASSWORD` | ✓ | ✓ | — |
| `DATABASE_URL` | ✓ | ✓ | — |
| `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` | ✓ | ✓ | — |
| `JWT_SECRET` | ✓ | ✓ (same) | — |
| `PAYSHIELD_DEV_API_KEY` | ✓ | — | — |
| `ENCRYPTION_KEY` | ✓ | ✓ (same) | — |
| `FRONTEND_URL` | ✓ | — | — |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | ✓ | — | — |
| `ENABLE_LLM_INVESTIGATOR` / `ENABLE_HUMAN_REVIEW` | ✓ | ✓ | — |
| `DATA_REGION` / `ENFORCE_RBAC` | ✓ | ✓ | — |
| `AUDIT_LOG_DIR=/app/store/audit_logs` | ✓ | ✓ | — |
| `VITE_API_URL` / `VITE_WS_URL` | — | — | ✓ |

Notes:
- `PAYSHIELD_DEV_API_KEY` is the value sent as the **`X-API-Key`** header
  (`api/dependencies.py`). The dashboard/callers must send it.
- The dashboard login defaults to `admin` / `ADMIN_PASSWORD`
  (`api/routes/auth.py`) — override via env.
- `FRONTEND_URL` is the CORS allow-list read by the API (`api/main.py`). Set it
  to the dashboard's public URL or the browser will block API calls.
- `REDIS_HOST` is a hostname, not a URL; there is no `REDIS_URL` in use.

## 7. Deploy order & behavior

1. **Redis → Postgres → Neo4j** first (Render/Aura).
2. Deploy `payshield-api`. Watch the build log: `pip install ... torch ... +cpu`
   then `requirements.txt`. Confirm `/health` returns `200` at
   `https://payshield-api.onrender.com/health`.
3. Deploy `payshield-worker`. It connects to Redis, registers the four agents,
   and heartbeats every 20s.
4. Deploy `payshield-dashboard`. Confirm `https://payshield-dashboard.onrender.com`
   loads the login page.

Startup order note: the Worker and API are now decoupled by the **Redis feed**
(`agent:feed:return_risk`) — the API pushes every scored order onto it, and the
Worker pops it and dispatches to the transaction/profile agents. This replaces
the old file-based handoff that only worked when both processes shared one disk
(`docker-compose.yml` mounts one volume into both).

**Health / verification:**
- `GET /health` → `200`
- `GET /admin/agents/health` → agents report `RUNNING` (worker heartbeats live
  in Redis)
- `POST /v1/return/score` (send `X-API-Key: <PAYSHIELD_DEV_API_KEY>`) → `SUCCESS`
- `POST /v1/score` (fraud scoring)
- Dashboard: login `admin`, then exercise a score and watch agent activity.

**Uptime caveat:** free-tier Web Services sleep after ~15 min and free
Background Workers do not auto-restart. Use a **paid** plan for 24/7
operation, or add an uptime monitor that pings `/health` every few minutes.

## 8. Troubleshooting

- **Dashboard shows API errors in the browser / CORS** → check `FRONTEND_URL`
  on the API equals the dashboard public URL.
- **Dashboard calls `localhost:8000`** → `VITE_API_URL` was unset/built wrong;
  Vite only reads `VITE_*`. Rebuild with it set.
- **Worker idle (agents `RUNNING` but nothing processed)** → confirm the API
  and Worker share the same Redis (same `REDIS_HOST`/`REDIS_PASSWORD`) and that
  `POST /v1/return/score` is being called. Check the feed key:
  `LRANGE agent:feed:return_risk 0 -1` via `redis-cli`.
- **Build fails on `pip install` / OOM** → use the Docker runtime
  (`docker/Dockerfile.api`), not a raw `pip install -r` Python build.
- **`/health` returns 503** → Redis is unreachable from the API service; check
  `REDIS_HOST` is the hostname (not a `redis://` URL) and password matches.
- **Audit/explanation files vanish on redeploy** → mount a Render Disk at the
  sub-paths in §5.
