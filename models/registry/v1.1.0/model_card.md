# PayShield GNN v1.1.0 — Model Card

**Version:** v1.1.0
**Release date:** 2026-08-15
**Status:** Production-ready (benchmark-validated on synthetic data)

## Model Details

- **Architecture:** HeteroConv + SAGEConv (mean aggr), 3 layers, hidden 128,
  target-user readout with transaction self-attention, 2-layer MLP head
- **Parameters:** 371,843
- **Training data:** synthetic UPI generator (data/synthetic/)
- **Lead metric:** PR-AUC (measure of minority-class ranking quality)
- **Framework:** PyTorch + PyTorch Geometric (HeteroConv, SAGEConv)

## What's New in v1.1.0

Compared to v1.0.0 (PR-AUC 0.198), this version:

- **Target-user readout** — replaces the global mean-pool readout, which
  diluted the scored user with neighbours, with direct extraction of the
  target-user embedding.
- **Transaction self-attention** — weights the target user's own transactions
  when aggregating into the graph representation.
- **Training objective aligned to PR-AUC** — early stopping and checkpoint
  selection monitor validation PR-AUC (not ROC-AUC), so the saved checkpoint
  is the best fraud-finder.
- **Five new features**:
  - Merchant: `is_shell`, `round_amount_share` (merchant 19 → 21 dims)
  - Transaction: `inter_arrival_gap`, `txn_count_5m`, `txn_count_1h`,
    `location_distance` (transaction 4 → 8 dims)
- **Optuna hyperparameter search** over hidden size, layer count, dropout,
  pos_weight, learning rate and batch size, scored on validation PR-AUC.

These changes lifted PR-AUC by **108%** relative (0.198 → 0.4125).

## Intended Use

Primary: detect anomalous UPI transactions via relational graph patterns
(shared-device mule rings, merchant collusion, burst attacks, account
takeover) as a conditional fusion input to PayShield's ensemble scoring
engine.

Out of scope: stand-alone fraud verdicts; real-time payments with latency
budgets under 1 ms (the GNN path is ~0.7 ms p99); jurisdictions not covered
by PayShield's EU AI Act conformity assessment.

## Evaluation Data

- synthetic UPI generator (data/synthetic/)
- 12,000 users, 1,000 merchants, 36,000 transactions
- Fraud prevalence: 5%
- Test split: 669 ego-graphs (60 positives), user-disjoint 80/10/10
- Seed: 42

## Test Metrics (held-out user-disjoint split)

| Metric | GNN v1.1.0 | Edge-free MLP |
|--------|------------|---------------|
| AUC-ROC | 0.7668 | 0.5395 |
| **PR-AUC** *(lead)* | **0.4125** | 0.1028 |
| FPR @ 90% recall | 0.4877 | 0.8196 |
| **PR-AUC lift** | — | **4.0×** |

*Why PR-AUC leads:* AUC-ROC is dominated by the legitimate majority in
imbalanced fraud; PR-AUC measures the minority (fraud) class directly.

## Known Limitations

- trained on synthetic data; real UPI traffic has different seasonality
- P2P recipients derived deterministically from merchant id (generator emits no recipient)
- burst/ATO patterns carry no graph-representable signal in the base feature
  schema (velocity, location distance), bounding absolute PR-AUC

## Fairness Evaluation

Demographic performance slices (SPD / EOD) are computed by
`models/fairness_audit.py` on synthetic gender, age-tier, and city-tier
splits. See the audit script for the latest numbers — they are **not**
hardcoded here to ensure they stay current with every run.

## Graph Schema

- **Node types:** user (5 features), merchant (21 features), device (4 features), transaction (8 features)
- **Edge types:** user→performed→transaction, transaction→to→merchant, user→used→device, user→transferred_to→user, device→shared_by→user
